## 1. Общие сведения

### 1.1. Назначение документа
Настоящее техническое задание определяет требования к разработке программного продукта для ведения учёта текущей доступности сотрудников компании силами отдела HR.

Программой могут пользоваться несколько сотрудников по очереди на одном ноутбуке, каждый под своей учётной записью.

**Программа должна обеспечивать:**
- Ведение единого справочника сотрудников
- Учёт текущего статуса доступности
- Хранение истории изменений
- Разграничение прав пользователей по ролям
- Ведение журнала действий пользователей
- Формирование стандартных отчётов
- Формирование отчётов по загружаемым пользователем Excel/PDF-шаблонам
- Импорт и экспорт данных
- Локальное защищённое хранение данных
- Работу без подключения к интернету

### 1.2. Наименование продукта (рабочее)
«Журнал доступности персонала» (название уточняется).

### 1.3. Цель разработки
- Заменить учёт «на бумаге / в разрозненных файлах» единым инструментом
- Обеспечить наглядное представление текущей занятости всех сотрудников
- Дать возможность за секунды узнать статус конкретного человека
- Автоматизировать подготовку сводных отчётов о занятости
- Обеспечить контроль действий пользователей
- Обеспечить базовую защиту данных при минимальной сложности использования

## 3. Функциональные требования

### 3.1. Карточка сотрудника

| Поле | Обязательность | Примечание |
|------|---------------|------------|
| Внутренний ID | Обязательно (авто) | Генерируется автоматически, скрыт |
| ФИО | Обязательно | Не уникальный идентификатор |
| Должность | Обязательно | Свободный текст или справочник |
| Филиал | Обязательно | Справочник |
| Департамент | Обязательно | Справочник, привязан к филиалу |
| Отдел | Опционально | Справочник, привязан к департаменту |
| Дата приёма | Резерв (скрыто) | Задел на будущее |
| Контакты | Резерв (скрыто) | Задел на будущее |
| Домашний адрес | Резерв (скрыто) | Повышенная чувствительность |
| СНИЛС/аналог | Резерв (скрыто) | Повышенная чувствительность |
| Тип занятости | Обязательно | Штатный / Временный / Подрядчик |
| Примечание | Опционально | Свободный текст |

**Особенности:**
- Каждый сотрудник идентифицируется по ID, а не по ФИО
- Справочники имеют внутренние ID (переименование не разрывает связи)
- Поля повышенной чувствительности маскируются по умолчанию

### 3.2. Учёт статуса доступности

**Принцип:** программа фиксирует статусы, но не принимает кадровые решения.

**Базовые статусы (редактируемые):**

| Статус | Требует дату окончания | Цвет |
|--------|------------------------|------|
| В офисе | Нет | Зелёный |
| Удалённо | Нет | Голубой |
| Командировка | Да | Оранжевый |
| Больничный | Опционально | Красный |
| Отпуск | Да | Фиолетовый |
| Отгул | Да | Жёлтый |
| Уволен / неактивен | Нет | Чёрный |

**Правила работы со статусами:**
- У активного сотрудника — один действующий статус
- Дата начала — сегодня (по умолчанию)
- При смене статуса программа автоматически закрывает предыдущий период
- Допускается внесение статуса с будущей датой
- Допускается внесение статуса задним числом
- Конфликт периодов обрабатывается через подтверждение HR

### 3.3. Состояние «Требует уточнения статуса»
- Автоматическая служебная пометка для сотрудников с истёкшим сроком статуса
- Отображение счётчика на главном экране
- Возможность перехода к списку таких сотрудников

### 3.4. Главный экран
- **Доска** — канбан-вид (колонки = статусы, карточки = сотрудники)
- **Таблица** — строки-сотрудники с цветовой заливкой статуса
- Переключение между видами
- Постоянные счётчики по статусам

### 3.5. Фильтрация и группировка
- Каскадные фильтры: Филиал → Департамент → Отдел
- Применяются ко всем видам и отчётам
- Группировка по статусу, филиалу или департаменту
- Кнопка «Показать всех» для сброса фильтров

### 3.6. Быстрый поиск
- Поиск по ФИО с фильтрацией по мере ввода
- Всплывающая карточка с текущим статусом и краткой историей

### 3.7. Импорт и экспорт сотрудников
- Импорт из XLSX/CSV: ФИО, должность, филиал, департамент, отдел, тип занятости
- Предпросмотр и проверка ошибок
- Защита от создания дублей
- Экспорт списка в XLSX («сырой» список)

### 3.8. Отчёты

#### 3.8.1. Стандартные формы

| Название отчёта | Форматы |
|-----------------|---------|
| Сводка «сейчас» | Excel / PDF |
| Отсутствующие за период | Excel / PDF |
| Временный персонал | Excel / PDF |
| История по сотруднику | Excel / PDF |
| Требуют уточнения | Excel / PDF |

#### 3.8.2. Пользовательские шаблоны

**Особенности:**
- Поддержка Excel и PDF шаблонов с фирменным оформлением
- Именованные поля/маркеры: `{{ФИО}}`, `{{Должность}}`, `{{Статус}}` и др.
- Табличные области с повторением строк
- Библиотека шаблонов с версионированием
- Проверка шаблона при загрузке
- Формирование отчёта без изменения исходного шаблона

**Жизненный цикл шаблона:**
1. Загрузка и проверка
2. Назначение параметров
3. Формирование отчёта
4. Сохранение результата

#### 3.8.3. Экспорт
- Стандартные отчёты → Excel и PDF
- Отчёты по шаблонам → в формате шаблона
- Дополнительно: Excel → PDF (при возможности)

### 3.9. Архивирование сотрудников
- Физическое удаление не используется
- Архивный сотрудник не отображается по умолчанию
- Вся история сохраняется
- Возможно восстановление из архива
- Статус «Уволен» — основание для архивации

## 4. Требования к безопасности и разграничению доступа

### 4.1. Учётные записи и роли

| Роль | Возможности | Ограничения |
|------|-------------|-------------|
| **Администратор** | Всё + управление учётными записями, настройки безопасности, просмотр журналов, полное управление шаблонами | — |
| **Сотрудник HR** | Работа с сотрудниками, статусами, справочниками, отчётами, импорт/экспорт, создание резервных копий | Не может управлять учётными записями и просматривать журнал действий |
| **Наблюдатель** | Просмотр, стандартные отчёты, отчёты по активным шаблонам | Не может изменять данные, импортировать, работать с резервными копиями |

**Правила:**
- Первая учётная запись — Администратор
- Элементы недоступных действий скрыты или заблокированы

### 4.2. Вход и защита пароля
- Вход по логину и паролю при каждом запуске
- Хэширование паролей с солью
- Автоблокировка через 15 минут бездействия (настраивается)
- Задержка после неудачных попыток входа (настраивается)

### 4.3. Защита базы данных
- Шифрование базы данных (SQLCipher)
- Отдельный ключ/мастер-пароль для Администратора
- Резервный код восстановления при первой настройке
- Каталог данных отдельно от каталога установки

### 4.4. Резервное копирование и восстановление
- Кнопка «Создать резервную копию»
- Зашифрованная копия с проверкой целостности
- Рекомендуется хранить несколько копий
- Восстановление только для Администратора

### 4.5. Журнал технических событий
- Запуск/остановка, ошибки, операции резервирования
- Пароли не записываются

### 4.6. Журнал действий пользователей
- Фиксируются: пользователь, дата/время, действие, запись, результат
- Включая операции с шаблонами
- Доступен только Администратору
- Фильтрация, экспорт в Excel
- Записи нельзя редактировать или удалять
