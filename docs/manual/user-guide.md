# Руководство пользователя (HR и Наблюдатель)

Документ описывает **фактическое поведение** приложения «Журнал доступности
персонала». Матрица прав — `domain/permissions.py` (`RoleCode.HR_EMPLOYEE`,
`RoleCode.OBSERVER`).

Подготовка Excel/PDF-шаблонов — отдельно:
[`report-templates-guide.md`](../report-templates-guide.md). Этот файл —
**использование** уже загруженных шаблонов и остальных функций.

Краткая шпаргалка — [`quick-reference.md`](quick-reference.md).

---

## 1. Вход и сессия

1. Запустите приложение (ярлык в меню или `personnel-availability`).
2. При **первом запуске** на этом компьютере — мастер создания учётной записи
   Администратора (см. [`administrator-guide.md`](administrator-guide.md)).
3. При обычном запуске — диалог **входа** (логин и пароль).
4. После неудачного входа действует **задержка** (~2 с) — защита от перебора
   (`services/authentication.py`, ADR-0004).
5. При **бездействии** сессия блокируется (таймаут настраивает Администратор,
   по умолчанию 15 мин). Разблокировка — повторный ввод пароля (`UnlockDialog`).

## 2. Главный экран

### 2.1. Режимы «Доска» и «Таблица»

Кнопки **Доска** / **Таблица** переключают представление одних и тех же
сотрудников (`ui/roster_panel.py`).

### 2.2. Поиск и фильтры

| Элемент | Действие |
|---|---|
| Строка поиска (шапка) | Фильтр по подстроке ФИО среди **уже загруженных** строк |
| Филиал → Департамент → Отдел | Каскадные списки |
| **Показать всех** | Сброс фильтров и поиска |
| **Только требующие уточнения** | Только сотрудники с флагом «Требует уточнения» |
| **Показать архив** | Показать архивных сотрудников (по умолчанию скрыты, EPIC-014) |
| Группировка | По статусу / филиалу / департаменту |

Фильтры **не пишут** в журнал действий — только навигация.

### 2.3. Счётчик «Требуют уточнения»

Клик по счётчику включает/выключает фильтр «Только требующие уточнения».
Состояние возникает, когда у сотрудника нет актуального статуса на сегодня или
истёк период без нового (`domain/status_clarification.py`).

### 2.4. Карточка на доске

Клик по сотруднику → всплывающее окно с краткой историей статусов → можно
открыть полную **карточку сотрудника**.

---

## 3. Карточка сотрудника

| Действие | HR | Наблюдатель |
|---|---|---|
| Просмотр ФИО, должности, оргструктуры | ✅ | ✅ |
| Создание / редактирование | ✅ | ❌ (поля отключены) |
| Домашний адрес, номер страхования | Только при `VIEW_SENSITIVE` / `EDIT_SENSITIVE` | ❌ (поля скрыты) |
| **В архив** / **Восстановить** | ✅ (с подтверждением) | ❌ |

При вводе ФИО HR видит подсказки **похожих имён** среди **активных** сотрудников
(`EmployeeService.search_by_name`, active-only).

---

## 4. Статусы доступности

- Назначение и просмотр истории — через карточку / сервис статусов (HR:
  `MANAGE_STATUSES`; Наблюдатель: только `VIEW_STATUSES`).
- При назначении пересекающихся периодов может потребоваться **подтверждение**
  (`ConfirmationRequiredError`).
- Статус **«Уволен / неактивен»** автоматически переводит сотрудника в **архив**
  (`services/status_history.py`).

---

## 5. Импорт и экспорт (HR)

Кнопки **Импорт** / **Экспорт** на главном экране (`Permission.IMPORT_EXPORT`).

**Импорт:** выбор файла → предпросмотр → подтверждение; предупреждения о
дубликатах ФИО (`services/employee_import.py`).

**Экспорт:** выгрузка текущих данных в файл (`services/employee_export.py`).

Наблюдатель: кнопки **отключены**.

---

## 6. Стандартные отчёты

Кнопка **Отчёты** → пять форм (`domain/reports.py`):

| Форма | Назначение | Основные параметры |
|---|---|---|
| Сводка «сейчас» | Снимок на дату | Филиал, департамент, отдел, статус, тип занятости, группировка |
| Отсутствующие за период | Кто отсутствовал | Период + фильтры оргструктуры |
| Временный персонал | Сотрудники с типом «временный» | Фильтры оргструктуры |
| История по сотруднику | Периоды статусов одного человека | Сотрудник + период |
| Требуют уточнения | Список для доработки статусов | Фильтры + группировка |

Экспорт в **Excel** и **PDF**. Формирование отчёта **не** пишется в журнал
действий (read-only, `StandardReportService`).

---

## 7. Отчёты по пользовательским шаблонам

1. **Шаблоны** на главном экране.
2. Выберите шаблон и версию → **Сформировать** → укажите путь сохранения.
3. Подготовка файла шаблона — см.
   [`report-templates-guide.md`](../report-templates-guide.md).

**Текущее ограничение:** UI **не запрашивает** значения маркеров — отчёт
формируется с **пустыми** полями (§8 guide). Это не ошибка установки.

| Действие | HR / Наблюдатель | Администратор |
|---|---|---|
| Просмотр активных шаблонов, генерация | ✅ | ✅ |
| Загрузка, архив, восстановление | ❌ | ✅ |

---

## 8. Что Наблюдатель не может делать

Наблюдатель (`RoleCode.OBSERVER`) — **только чтение**:

- Не создаёт и не редактирует сотрудников, статусы, справочники.
- Не импортирует/экспортирует.
- Не создаёт резервные копии и не восстанавливает БД.
- Не управляет учётными записями и шаблонами.
- Не видит журнал действий пользователей.

Отключённые кнопки на главном экране — ожидаемое поведение, не сбой прав.
