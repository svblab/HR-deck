# Руководство администратора

Для роли **Администратор** (`RoleCode.ADMINISTRATOR`) — полный доступ по
`domain/permissions.py`. Общие сценарии HR — в [`user-guide.md`](user-guide.md).

Процедуры «что делать при сбое» — в [`maintenance-runbook.md`](maintenance-runbook.md).

Установка и обновление пакета — [`deployment-guide.md`](deployment-guide.md),
краткая памятка — [`install-update-quick.md`](install-update-quick.md).

## 1. Учётные записи

Доступ: кнопка пользователя на главном экране → **Учётные записи**
(`ui/auth_dialogs.py` → `AccountsDialog`).

| Операция | Примечание |
|---|---|
| Создание учётки | Логин, пароль, роль (HR / Наблюдатель / Администратор) |
| Смена пароля | Администратор может сбросить пароль пользователя |
| Деактивация | `is_active = 0`; **удаления учёток нет** (append-only аудит, EPIC-005) |
| Настройки безопасности | Таймаут неактивности, вкл/выкл блокировки |

### 1.1. Инвариант «один активный Администратор»

В системе допускается **не более одного активного** Администратора
(`AccountManagementService._reject_second_active_administrator`).

- Нельзя создать второго активного Администратора, пока есть первый.
- Нельзя **деактивировать** или **понизить** последнего активного Администратора.

Планируйте передачу роли: сначала создайте нового Администратора после
освобождения слота, либо используйте восстановление по коду (§2).

## 2. Резервный код и восстановление пароля

При **первичной настройке** (`BootstrapService.initial_administrator_setup`)
генерируется **одноразовый резервный код** — показывается **один раз**, в БД
хранится только хэш (ADR-0003).

**Сброс пароля Администратора:**

1. На экране входа — **Восстановление по коду**.
2. Введите резервный код и новый пароль.
3. Старый код **гасится**; выдаётся **новый** код (показать и сохранить).

**Если потеряны и пароль, и резервный код** — восстановления **нет**. Единственный
путь — восстановление **файла БД** из резервной копии (см. runbook).

## 3. Журнал действий пользователей

Кнопка **Журнал** (шестерёнка) — только у Администратора
(`Permission.VIEW_USER_ACTION_LOG`).

- Фильтры: период, пользователь, тип действия, сущность (`ui/action_log_dialog.py`).
- Экспорт в файл.
- Записи **нельзя удалить** (append-only, миграция `0002`).

**Что не аудируется:** просмотр главного экрана, фильтры, формирование
**стандартных** отчётов (read-only). Аудируются изменения данных, вход,
операции с шаблонами, бэкап/restore и т.д.

## 5. Резервное копирование и восстановление

Кнопка **⚙** (настройки) → диалог резервного копирования (`ui/backup_dialog.py`).

### 5.1. Создание копии

1. **Создать копию…** → выберите каталог (можно `~/.local/share/.../backups/`).
2. Копируются `personnel.db` + sidecar `.keywrap`.
3. После копирования выполняется **проверка целостности**.

### 5.2. Восстановление

1. **Восстановить…** → выберите файл `.db` копии.
2. Подтвердите предупреждение.
3. Автоматически создаётся **pre-restore** копия текущего состояния.
4. Live-файлы заменяются атомарно; приложение переподключается к БД.

Подробные runbook-шаги при сбоях — [`maintenance-runbook.md`](maintenance-runbook.md).

---

## 6. Справочники и прочее

Администратор наследует все права HR плюс:

- Управление учётными записями и настройками безопасности.
- Полный журнал действий и технических событий (просмотр).
- Управление шаблонами.
- Восстановление из бэкапа (`RESTORE_BACKUP` — только Администратор).
