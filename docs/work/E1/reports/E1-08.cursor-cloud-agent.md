## Находки (§0.2)
1. Текст карточки (критерий 2) описывает status_history так, будто это дочерняя таблица employment_types. Фактически на employment_types ссылается только employees.employment_type_id (`0001:91`, `0011:23`); status_history.status_id ссылается на availability_statuses. Симптом: ложное ожидание FK от status_history к employment_types при проверке rebuild. Предполагаемая причина: краткая формулировка приёмки. Предполагаемый объём: правка текста карточки (docs). По GO формулировку не меняли.
2. src/data/directories.py на origin/master не проходит ruff format --check (участки около строк 75-81 и 268-272 по ruff format --diff на master). Симптом: format-diff ненулевой на файле до E1-08. Предполагаемая причина: исторический долг формата. Предполагаемый объём: отдельная format-карточка. В E1-08 файл форматом не трогали.
3. get_by_code оставлен без изменений и после появления строк с owner_branch_id может стать неоднозначным для несистемных кодов (несколько строк с одним code). Симптом: lookup только по code без владельца. Предполагаемая причина: сознательное сохранение API для forbidden src/services/directories.py. Предполагаемый объём: аудит вызывающих мест в E1-09 и E1-13.
4. Временное отклонение домашнего филиала (owner_branch_id не сверяется с домашним филиалом записи) не входит в объём этой карточки. Симптом: отсутствие такой проверки в схеме/data-layer E1-08. Предполагаемая причина: зона ответственности E4. Предполагаемый объём: карточки E4.
