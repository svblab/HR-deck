## Card wording
Критерий 2 карточки говорит «parametrized over all six codes … and case/whitespace variants» для `rename_system_codes_rejected`. `rename_employment_type` принимает `id`, не код: варианты регистра/пробелов к rename не применимы. Варианты проверены в `test_create_reserved_code_rejected` (код, `upper()`, пробелы вокруг, `upper()` с пробелами). Rename и hide параметризованы по шести хранимым кодам. Hide: все шесть отклоняются; `unarchive_employment_type` для системных кодов остаётся разрешённым.

## Что сделано
1. `SYSTEM_EMPLOYMENT_TYPE_CODES` включает `staff`, `temporary`, `contractor`, `dismissed`, `transferred`, `erroneous`. `is_system_employment_type_code` по-прежнему `strip().casefold()`.
2. `rename_employment_type` отвергает системный код через `DirectoryError("system employment type '<code>' cannot be renamed")`.
3. `archive_employment_type` / `_set_employment_type_archived(..., archived=True)` по-прежнему использует `is_system_employment_type_code`; после расширения множества скрытие запрещено для всех шести. Unarchive не блокируется.
4. `create_employment_type` проверяет резерв **до** duplicate-check; сообщение `system employment type '<clean_code>' cannot be created`. Duplicate для `intern` («code already exists») сохранён.
5. Запись `archives_record` через API не добавлялась. Сервисный create оставляет столбец по умолчанию 0; rename/hide/unhide его не трогают.
