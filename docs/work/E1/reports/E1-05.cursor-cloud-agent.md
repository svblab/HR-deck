## Что сделано
1. Миграция `0021_employee_transfer_target_branch.sql`: только `ALTER TABLE employees ADD COLUMN transfer_target_branch_id INTEGER REFERENCES branches(id)`. Без rebuild, без `PRAGMA foreign_keys` off, без триггеров, без backfill.
2. Data layer: `EmployeeRecord.transfer_target_branch_id` последним полем; колонка последней в `_SELECT`; `_row` читает `row[17]`. Запись — `EmployeeRepository.set_transfer_target_branch_id(..., *, updated_at, transfer_target_branch_id)` (keyword-only; параметр обязателен, без default). Почему не `update`/`create`/`apply_sync_row`: карточка требует, чтобы существующий `update` и `apply_sync_row` не сбрасывали поле; `apply_sync_row` запрещено менять.
3. Domain [B]: только `EmployeeCard.transfer_target_branch_id: int | None = None` последним полем. `EmployeeCreateInput` / `EmployeeUpdateInput` / `SensitiveEmployeeInput` не трогались.
