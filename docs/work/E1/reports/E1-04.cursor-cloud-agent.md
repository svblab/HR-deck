## Card wording
Чтение карточки / ADR §4.1 / ТЗ §4.10.2 для `_classify`:
- при совпадении `external_id` с локальной карточкой: CONFLICT, если нормализованное ФИО отличается **или** филиал отличается; EXACT только если оба совпали;
- сравнение филиала: строка `row["branch_external_id"]` с `external_id` локального филиала сотрудника, прочитанным через `BranchRepository.get(local.branch_id)`; пакетный `branch_external_id` **не** резолвится через `get_by_external_id`; неизвестный branch external id пакета поэтому даёт CONFLICT.
ADR §4.1 и TZ §4.10.2 этому чтению не противоречат. Исключение TZ §15.7.5 для входящей обезличенной карточки не реализовано (E10); пока его нет — другое ФИО на импорте есть CONFLICT (ADR §4.1).

## Verbatim TZ §4.10.2 point 2
Из `docs/TZ-v2.md`, раздел «4.10. Сопоставление карточек при импорте», пункт 2:

2. Если филиал-владелец или ФИО не совпали, класс CONFLICT: пакет отклоняется целиком. Это сигнал нарушения целостности: ФИО постоянно (4.4.3), филиал карточки неизменяем (2.3.2). Исключение (15.7.5): если входящая карточка обезличена (15.7) и её `external_id` и филиал-владелец совпадают с локальной карточкой, несовпадение ФИО не является конфликтом: локальная карточка обезличивается (обязательно, независимо от отметки строки в сценарии «Выборочный импорт», 7.18), прежние персональные данные никогда не восстанавливаются, и пакет по этой причине не отклоняется. Несовпадение филиала-владельца остаётся CONFLICT даже для обезличенной карточки.

## Что сделано
1. `EmployeeReconciliationService._classify`: EXACT только при совпадении нормализованного ФИО и `branch_external_id` (plain string vs local branch external_id через `BranchRepository.get`). Иначе CONFLICT.
2. Целостный отказ пакета остаётся на `_HARD_BLOCKING` в `employee_sync_import.py` (без правок этого файла). Доказано unit-тестом: CONFLICT по филиалу + валидная NEW-строка → `EmployeeSyncConflictError`, ничего не записано.
3. Обезличивание не добавлялось. Тест симулирует локальное обезличивание через `EmployeeRepository.update(... full_name="обезличено" ...)` только в тесте; старый пакет с исходным ФИО → CONFLICT.
4. `_package_employee_row` принимает optional `branch_external_id`; EXACT и name-conflict передают реальный branch external id; новый тест `test_adr0010_reconciliation_conflict_on_branch_id_mismatch`.
