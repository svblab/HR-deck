## Цель
На `origin/master` `src/ui/directories_dialog.py` управляет только видами занятости; **отдельного раздела статусов доступности нет** (`git grep -n availability origin/master -- src/ui/directories_dialog.py` -> нет совпадений). Добавить редактирование дополнительных статусов **филиала-владельца** по образцу E1-14 (создание, переименование, скрытие и возврат, изменение порядка `sort_order`; удаления нет); **селектор филиала-владельца** (`owner_branch_id`); базовый набор из посева `0001` не редактируется как дополнительный. Вызовы — через `AvailabilityStatusService` (E1-20). сигнатура `DirectoriesDialog(directories, session, parent=None, *, availability_statuses: AvailabilityStatusService | None = None)` (новый параметр только именованный и после `parent`; существующие вызовы с двумя и тремя позиционными аргументами не ломаются); `src/ui/roster_panel.py:423` передаёт `availability_statuses=self._availability_statuses` именованным аргументом; раздел статусов показывается при наличии сервиса и права просмотра `VIEW_STATUSES` (его требует `list_statuses`, `src/services/availability_statuses.py:44-46`); кнопки изменения активны только при `MANAGE_DIRECTORIES`, как у остальных панелей диалога (`src/ui/directories_dialog.py:45`); Наблюдатель видит список в режиме просмотра (ТЗ 1.7, строки 9 и 10 матрицы: просмотр справочников — да, правка — нет); порядок статусов меняется через существующий `update_status_display(status_id, *, color_hex, sort_order)` (`src/services/availability_statuses.py:92`) с неизменным `color_hex`. E4 подставит домашний филиал по умолчанию.
