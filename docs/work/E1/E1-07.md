## Цель
Действие «В архив» показывает только три архивирующих вида в порядке таблицы 3.4; для `transferred` — выбор филиала назначения (не скрытый, не домашний); обычный список вида на форме действующей карточки не содержит архивирующих кодов; в UI есть фильтр ошибочных записей (`erroneous`); фильтр архива по домашнему филиалу не реализуется (E4).

## Не входит
Логика сервиса архива (E1-06); домашний филиал в архиве (E4); отчёты, исключающие erroneous (E12); обмен и пакет (E1-09).

## Входные условия
1. E1-06 в статусе `done`.
2. `git show origin/master:src/ui/employee_card_form.py | sed -n '220,224p'` -> все активные виды в комбо.
3. `git show origin/master:src/ui/archive_dialog.py | sed -n '73,75p'` -> диалог без выбора вида.

## Критерии приёмки
1. `pytest tests/unit/test_archive_dialog.py tests/unit/test_employee_card_employment_combo.py tests/qt/test_archive_flow.py -q` -> проходит; комбо архива — ровно три кода; комбо карточки — без `dismissed`, `transferred`, `erroneous`; выбор скрытого филиала назначения блокируется.
2. `rg -n "erroneous" src/ui/` -> фильтр списка или эквивалент по 4.7.2 присутствует.
3. `ruff check` по `allowed_paths` -> без замечаний.
4. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт.

## Что оставить после себя
Правки UI и тесты, отчёт с «NOT VERIFIED» и «Для следующего».
