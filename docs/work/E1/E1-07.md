## Цель
Действие «В архив» (`src/ui/employee_card_form.py:385-388`) показывает только три архивирующих вида; для `transferred` — выбор филиала назначения (не скрытый, не домашний); комбо вида на форме действующей карточки без архивирующих кодов; UI вызывает **новые** методы E1-06 (`archive_employee_with_archiving_code`, `restore_employee_with_employment_type_code`), не удаляет старые в сервисе. В форме «Архив» — флажок «Показывать ошибочные записи», **снят по умолчанию**. `_reload` передаёт `RosterFilters(name_query=query, include_erroneous=<состояние флажка>)`; переключение флажка вызывает `_reload`. После `list_rows` по-прежнему отбор `row.is_archived`. Режима «только ошибочные» нет.

**Восстановление из архива** (`_restore_selected` :184, `_restore_and_assign_status` :196 в `archive_dialog.py`): перевод на `restore_employee_with_employment_type_code` с кодом, выбранным пользователем. ТЗ §4.8 п.3: «**Вид занятости не восстанавливается автоматически**: пользователь выбирает его заново (ADR-0011).» ТЗ §4.8 п.4: признак «требует уточнения» (колонка `needs_org_review` по E1-06). ТЗ §3.8.1 п.1: «При назначении статуса и вида занятости в записях своего филиала предлагаются базовый набор (всегда) и справочник домашнего филиала (без скрытых записей).»

## Не входит
Логика `RosterRow` / `apply_filters` / `_to_row` (E1-18); логика сервиса архива (E1-06); удаление deprecated методов (E1-12); домашний филиал в архиве (E4); обмен и пакет (E1-09); главный экран (`roster_panel.py` — только действующие карточки, ТЗ 4.5.4).
