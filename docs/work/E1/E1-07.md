## Цель
Действие «В архив» (`src/ui/employee_card_form.py:385-388`) показывает только три архивирующих вида; для `transferred` — выбор филиала назначения (не скрытый, не домашний); комбо вида на форме действующей карточки без архивирующих кодов; UI вызывает **новые** методы E1-06 (не удаляет старые в сервисе). В форме «Архив» — флажок «Показывать ошибочные записи», **снят по умолчанию**. `_reload` передаёт `RosterFilters(name_query=query, include_erroneous=<состояние флажка>)`; переключение флажка вызывает `_reload`. После `list_rows` по-прежнему отбор `row.is_archived`. Режима «только ошибочные» нет.

**Восстановление из архива** (оба пути в `archive_dialog.py`): на `origin/master` `_restore_selected` (`:184`) и `_restore_and_assign_status` (`:196`) вызывают одноаргументный `restore_employee`. По ТЗ §4.8 п.3 вид занятости **не восстанавливается автоматически** — пользователь выбирает неархивирующий вид заново; по ТЗ §4.8 п.4 и карточке E1-06 восстановление с выбранным видом выставляет `needs_org_review`. Обе команды переводятся на **новый** API восстановления E1-06 с явным кодом вида, выбранным пользователем в UI (отдельный диалог или элемент формы — на усмотрение исполнителя в рамках `allowed_paths`).

## Не входит
Логика `RosterRow` / `apply_filters` / `_to_row` (E1-18); логика сервиса архива (E1-06); удаление deprecated методов (E1-12); домашний филиал в архиве (E4); обмен и пакет (E1-09); главный экран (`roster_panel.py` — только действующие карточки, ТЗ 4.5.4).
