## Цель
В таблице `employees` есть nullable `transfer_target_branch_id` с внешним ключом на `branches`; доменная модель и слой данных читают и пишут поле; миграция не отключает внешние ключи.

## Не входит
Правила архива, которые заполняют поле (E1-06); UI выбора филиала назначения (E1-07); сериализация `transfer_target_branch_external_id` в пакете (E1-09); проверка скрытого филиала при архиве (E1-06, ТЗ 9.9.4).

## Входные условия
1. `git show origin/master:src/data/migrations/0001_initial_schema.sql | sed -n '1,120p'` -> у `employees` нет `transfer_target_branch_id`.
2. `python3 scripts/work_status.py` -> код 0.

## Критерии приёмки
1. Новая миграция после последней на `origin/master`: `rg -l transfer_target_branch_id src/data/migrations/` -> один новый файл; внутри нет `PRAGMA foreign_keys=OFF`.
2. `pytest tests/unit/test_employee_transfer_target_column.py -q` -> проходит; после миграции `PRAGMA table_info(employees)` содержит столбец; FK на `branches(id)` включён.
3. `ruff check src/data/employees.py src/domain/employee.py tests/unit/test_employee_transfer_target_column.py` -> без замечаний.
4. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт; в пределах бюджета.
5. До смены статуса на done: поле в сервисе архива ещё не обязано использоваться — это E1-06.

## Что оставить после себя
Миграция, правки data/domain, тест, отчёт с «NOT VERIFIED» и «Для следующего».

## Заметки планировщика
Бюджет уменьшен (S): только схема и доступ к полю. E1-06 зависит от этой карточки. Поле справочное (4.6.5); очистка после восстановления не выполняется (решение Maintainer 5, адденд §3.2).
