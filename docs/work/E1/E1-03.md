## Цель
`EmployeeService.update_employee` отвергает изменение `full_name` или `branch_id` после создания; форма карточки после сохранения новой записи делает эти поля только для чтения (подсказка 9.7.1). Триггер БД на столбцы не добавляется.

## Не входит
CONFLICT и EXACT на импорте (E1-04); обезличивание (E10, ADR N6); запреты в репозитории «любая перезапись» (адденд §4.1); архив и восстановление (E1-06).

## Входные условия
1. `git show origin/master:src/services/employees.py | sed -n '115,132p'` -> оба поля пишутся без сравнения с сохранёнными.
2. `git show origin/master:src/ui/employee_card_form.py | sed -n '86,89p'` -> поля доступны после создания.

## Критерии приёмки
1. `pytest tests/unit/test_employee_immutable_fields.py tests/unit/test_employee_card_form_immutable.py -q` -> проходит; сервис: создание записывает ФИО и филиал; `update_employee` с другим ФИО или `branch_id` -> ошибка до записи; с теми же значениями -> успех.
2. UI-тест (Qt offscreen или тест виджета): после успешного создания `full_name` и виджет филиала недоступны для редактирования.
3. `rg "CREATE TRIGGER" src/data/migrations/` после PR -> нет нового триггера на `employees.full_name` или `employees.branch_id`.
4. `ruff check` и `mypy` по файлам из `allowed_paths` -> без ошибок.
5. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт.

## Что оставить после себя
Правки сервиса и формы, тесты, отчёт с «NOT VERIFIED» и «Для следующего».

## Заметки планировщика
Исключение Maintainer: сервис и форма в одной карточке (ADR-0011 §4.1). Импорт EXACT с теми же значениями остаётся в E1-04. Ссылки: `src/services/employees.py:90-94`, `:115-132`; форма `:86-89`. Инвариант A8 не отменяется.
