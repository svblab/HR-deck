## Цель
Схема `employment_types` получает `owner_branch_id`, частичные уникальные индексы (базовый `code` при NULL-владельце; пара `(owner_branch_id, code)` для дополнительных), снятие столбцового `UNIQUE` на `code` без `PRAGMA foreign_keys=OFF`; колонка порядка сортировки (3.8.3); сервис проверяет формат кода §3 ADR-0010 и резерв; UI редактирует порядок и дополнительные записи домашнего филиала.

## Не входит
Таблицы `availability_statuses` и их миграция владельца (отдельная карточка схемы или E2+); строки пакета `employment_types` (E1-09); экспорт/импорт пакета (E1-09); дата окончания и цвет вида (открытый вопрос адденду ADR-0011).

## Входные условия
1. E1-02 в статусе `done`.
2. `git show origin/master:src/data/migrations/0001_initial_schema.sql | sed -n '64,64p'` -> глобальный `UNIQUE` на `code`.
3. `git show origin/master:src/data/directories.py | sed -n '427,430p'` -> `get_by_code` не различает владельца.

## Критерии приёмки
1. `pytest tests/unit/test_employment_type_owner_schema.py tests/unit/test_employment_type_code_format.py tests/integration/test_employment_type_unique_indexes.py -q` -> проходит; два филиала могут иметь один и тот же дополнительный `code`; базовые коды по-прежнему уникальны глобально; миграция с `PRAGMA foreign_keys=ON` на всех шагах.
2. `rg "foreign_keys=OFF" src/data/migrations/*employment*` -> нет совпадений.
3. Формат кода: тесты отклоняют пустую строку, `Staff`, резервный `staff` для дополнительной записи; принимают `vacation_extra` для владельца.
4. `ruff check` и `mypy` по затронутым модулям -> без ошибок.
5. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт; строк кода+тестов не более 500+900.
