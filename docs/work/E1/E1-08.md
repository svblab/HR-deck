## Цель
Только схема и data-layer: `employment_types.owner_branch_id`, колонка `sort_order`, снятие столбцового `UNIQUE` на `code` **без** `PRAGMA foreign_keys=OFF` (ТЗ §2.4.5, ADR-0010 §4); два частичных уникальных индекса (ADR-0010 §4); lookup по паре `(owner_branch_id, code)` в `src/data/directories.py`.

**Перестройка таблицы** (одна транзакция раннера, `PRAGMA foreign_keys=ON` на соединении; spike B1 2026-11-04):
1. `PRAGMA defer_foreign_keys=ON`
2. `CREATE TEMP TABLE _employment_types_backup AS SELECT * FROM employment_types`
3. `DROP TABLE employment_types`
4. `CREATE TABLE employment_types` под финальным именем **без** столбцового `UNIQUE` на `code`, с `owner_branch_id INTEGER NULL REFERENCES branches(id)`, `sort_order INTEGER NOT NULL DEFAULT 0`, `archives_record` и прочими столбцами как до миграции
5. `INSERT INTO employment_types (id, code, name, is_archived, created_at, updated_at, owner_branch_id, archives_record, sort_order) SELECT id, code, name, is_archived, created_at, updated_at, NULL, archives_record, 0 FROM _employment_types_backup`
6. `CREATE UNIQUE INDEX idx_employment_types_system_code ON employment_types(code) WHERE owner_branch_id IS NULL`
7. `CREATE UNIQUE INDEX idx_employment_types_owner_code ON employment_types(owner_branch_id, code) WHERE owner_branch_id IS NOT NULL`
8. `DROP TABLE _employment_types_backup`

В SQL миграции **нет** `PRAGMA defer_foreign_keys=OFF` и **нет** `PRAGMA foreign_key_check` (проверка — в integration-тестах; `apply_pending_migrations` в `src/data/migrations.py` не вызывает `foreign_key_check` после миграции).

**Spike (проверено):** B1 (шаги 1–8 выше, без defer OFF) — COMMIT успешен. B2 (INSERT без строки родителя, на которую ссылается `employees`) — COMMIT с `IntegrityError: FOREIGN KEY constraint failed`. Порядок `CREATE …_new`, copy, `DROP`, `RENAME` с `defer_foreign_keys=ON` — `PRAGMA foreign_key_check` пустой, но **COMMIT** падает с `FOREIGN KEY constraint failed` (spike 2). Образец `0010` с NULL дочернего FK **неприменим** — `employees.employment_type_id` NOT NULL (`0001_initial_schema.sql:91`), `status_history.status_id` NOT NULL (`0001:105`). `PRAGMA foreign_keys=OFF` **внутри** транзакции раннера не отключает enforcement (`0013_position_branch.sql`). `PRAGMA foreign_keys=OFF` **вне** транзакции — **запрещено** ТЗ-v2 §2.4.5 п.5 (`docs/TZ-v2.md:366`). **`PRAGMA defer_foreign_keys=OFF` перед COMMIT** (STEP 0, B2): при нарушенных FK `foreign_key_check` не пустой, но **COMMIT успешен** — **не использовать** в миграции.
