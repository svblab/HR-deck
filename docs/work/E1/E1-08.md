## Цель
Только схема и data-layer: `employment_types.owner_branch_id`, колонка `sort_order`, снятие столбцового `UNIQUE` на `code` **без** `PRAGMA foreign_keys=OFF` (ТЗ §2.4.5, ADR-0010 §4); два частичных уникальных индекса (ADR-0010 §4); lookup по паре `(owner_branch_id, code)` в `src/data/directories.py`.

**Перестройка таблицы** (одна транзакция раннера, соединение с `PRAGMA foreign_keys=ON`; spike 2026-11-04 на схеме после `0019`):
1. `PRAGMA defer_foreign_keys=ON`
2. `CREATE TEMP TABLE _employment_types_backup AS SELECT * FROM employment_types`
3. `DROP TABLE employment_types`
4. `CREATE TABLE employment_types` под финальным именем **без** столбцового `UNIQUE` на `code`, с `owner_branch_id INTEGER NULL REFERENCES branches(id)`, `sort_order INTEGER NOT NULL DEFAULT 0`, сохранением `archives_record` и прочих столбцов
5. `INSERT INTO employment_types … SELECT … FROM _employment_types_backup` (сохранить `id`)
6. `CREATE UNIQUE INDEX idx_employment_types_system_code ON employment_types(code) WHERE owner_branch_id IS NULL`
7. `CREATE UNIQUE INDEX idx_employment_types_owner_code ON employment_types(owner_branch_id, code) WHERE owner_branch_id IS NOT NULL`
8. Пересоздать индексы/триггеры/views, если появятся на таблице (на spike-БД после `0019` в `sqlite_master` только сами таблицы `employment_types` / дочерние `employees`, `status_history`; отдельных trigger/index на `employment_types` нет)
9. `DROP TABLE _employment_types_backup`
10. `PRAGMA defer_foreign_keys=OFF`
11. `PRAGMA foreign_key_check` -> пустой результат

**Spike (не выдумывать):** образец `0010` с NULL дочернего FK **неприменим** — `employees.employment_type_id` NOT NULL (`0001_initial_schema.sql:91`). Порядок `CREATE …_new`, copy, `DROP`, `RENAME` **без** `defer_foreign_keys` падает на `DROP`/`COMMIT` с `FOREIGN KEY constraint failed` при живых строках `employees`. `PRAGMA foreign_keys=OFF` **внутри** транзакции раннера не отключает enforcement (`0013_position_branch.sql`: `PRAGMA foreign_keys` остаётся 1; nonempty `positions` — `NOT NULL` на `branch_id`, не обход OFF). `PRAGMA foreign_keys=OFF` **вне** транзакции rebuild проходит, но **запрещено** ТЗ-v2 §2.4.5 п.5 (`docs/TZ-v2.md:366`) без решения Johan.
