## Цель
Новые методы `EmployeeService`:
- `archive_employee_with_archiving_code(self, employee_id: int, *, archiving_code: str, transfer_target_branch_id: int | None = None) -> None` — явный архивирующий код (`dismissed`, `transferred`, `erroneous`); для `transferred` обязателен валидный `transfer_target_branch_id`;
- `restore_employee_with_employment_type_code(self, employee_id: int, *, employment_type_code: str) -> None` — неархивирующий код вида занятости после восстановления.

Оба меняют `is_archived`, `employment_type_id` и при необходимости `transfer_target_branch_id` атомарно в одном `_mutate`. Старые `archive_employee(self, employee_id: int)` и `restore_employee(self, employee_id: int)` **сохраняются**, помечены deprecated в docstring, поведение одноаргументного пути до E1-12 не ломается. Восстановление новым методом выставляет `employees.needs_org_review` (ADR-0009 «требует внимания»; ТЗ §4.8 п.4 «требует уточнения» — та же колонка).

Файлы `tests/unit/test_employee_archive_service.py` и `tests/integration/test_employee_archive_atomicity.py` **создаются этой карточкой** (на `origin/master` отсутствуют).

## Не входит
UI диалога и перевод вызовов UI на новые методы (E1-07); обновление тестов/UI, вызывающих одноаргументные методы (E1-12); обмен `is_archived` (E1-09); фильтр архива по домашнему филиалу (E4).
