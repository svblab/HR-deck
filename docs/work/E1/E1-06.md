## Цель
Новые методы `EmployeeService`:
- `archive_employee_with_archiving_code(self, employee_id: int, *, archiving_code: str, transfer_target_branch_id: int | None = None) -> None` — явный архивирующий код (`dismissed`, `transferred`, `erroneous`); для `transferred` обязателен валидный `transfer_target_branch_id`;
- `restore_employee_with_employment_type(self, employee_id: int, *, employment_type_id: int) -> None` — после восстановления выставляет неархивирующий вид по **id** (код один неоднозначен при owner-scoped `code` после E1-08).

Оба меняют `is_archived`, `employment_type_id` и при необходимости `transfer_target_branch_id` атомарно в одном `_mutate`. `restore_employee_with_employment_type` проверяет, что `employment_type_id` входит в список `DirectoryService.list_assignable_employment_types_for_branch` (E1-22) для `employees.branch_id` карточки; для списка внутри `EmployeeService` создаётся `DirectoryService(self._conn, self._session, authz=self._authz, clock=self._clock)` (конструктор `EmployeeService` не меняется: `self._conn`, `self._session`, `self._authz`, `self._clock` — `src/services/employees.py:62-65`, `src/services/directories.py:39-46`). Восстановление требует `Permission.MANAGE_EMPLOYEES` (`employees.py:214` — HR и Administrator); обе роли имеют `Permission.VIEW_DIRECTORIES` (HR — `src/domain/permissions.py:70`; Administrator — `_ALL`, `:83-84`), поэтому вызов списка E1-22 разрешён.

Старые `archive_employee(self, employee_id: int)` и `restore_employee(self, employee_id: int)` **сохраняются**, deprecated в docstring, до E1-12. Восстановление выставляет `employees.needs_org_review`; `transfer_target_branch_id` не очищается.

Файлы `tests/unit/test_employee_archive_service.py` и `tests/integration/test_employee_archive_atomicity.py` **создаются этой карточкой** (на `origin/master` отсутствуют).
