## Цель
Архив требует явный архивирующий код (`dismissed`, `transferred`, `erroneous`); тихий `dismissed` и архив без вида убраны; для `transferred` обязателен валидный филиал назначения; `is_archived`, `employment_type_id` и `transfer_target_branch_id` меняются атомарно в одном `_mutate`; восстановление только с новым неархивирующим видом и признаком «требует уточнения».

## Не входит
UI диалога (E1-07); списки видов на форме действующей карточки (E1-07); фильтр ошибочных в списках (E1-07); обмен `is_archived` (E1-09); фильтр архива по домашнему филиалу (E4).

## Входные условия
1. E1-01, E1-02, E1-05 в статусе `done`.
2. `git show origin/master:src/services/employees.py | sed -n '186,211p'` -> архив без выбора вида; `sed -n '213,228p'` -> восстановление только снимает флаг.

## Критерии приёмки
1. `pytest tests/unit/test_employee_archive_service.py tests/integration/test_employee_archive_atomicity.py -q` -> проходит; отказ: филиал назначения скрыт, равен домашнему или отсутствует для `transferred`; после отказа строка карточки без изменений; успешный архив — все три поля согласованы.
2. `rg -n "resolve_archive_employment_type|dismissed" src/domain/employment_types.py src/services/employees.py` -> нет тихого пути без явного кода от UI/сервиса (поведение по ADR §3.1).
3. Восстановление: тест — новый неархивирующий вид и флаг «требует уточнения»; `transfer_target_branch_id` не очищается.
4. `ruff check` и `mypy` по затронутым модулям -> без ошибок.
5. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт.

## Что оставить после себя
Правки сервиса/домена, тесты, отчёт с «NOT VERIFIED» и «Для следующего».
