## Цель
Новые методы сервиса принимают явный архивирующий код (`dismissed`, `transferred`, `erroneous`) и для `transferred` — валидный `transfer_target_branch_id`; `is_archived`, `employment_type_id` и `transfer_target_branch_id` меняются атомарно в одном `_mutate`. Старые `archive_employee(self, employee_id: int)` и `restore_employee(self, employee_id: int)` **сохраняются**, помечены deprecated в docstring карточки/кода, поведение одноаргументного пути до E1-12 не ломается для существующих вызовов. Восстановление с новым неархивирующим видом выставляет `employees.needs_org_review` (ADR-0009 «требует внимания»; ТЗ 4.8.4 «требует уточнения» — та же колонка, новый столбец не вводится).

## Не входит
UI диалога и перевод вызовов UI на новые методы (E1-07); обновление тестов/UI, вызывающих одноаргументные методы (E1-12); обмен `is_archived` (E1-09); фильтр архива по домашнему филиалу (E4).
