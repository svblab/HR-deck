## Цель
`DirectoryService.list_assignable_employment_types_for_branch(self, branch_id: int)` — единый источник списка для комбо вида на карточке действующего сотрудника (`src/ui/employee_card_form.py:220-224` сегодня вызывает `list_employment_types(active_only=True)`; заменить на этот метод в E1-07). По `branch_id` карточки возвращает записи с `archives_record=0` (не архивирующие коды): **базовые** (`owner_branch_id IS NULL`, не скрытые) всегда; **дополнительные** с `owner_branch_id = branch_id`, не скрытые; без кодов с `archives_record=1`. Порядок — ТЗ §3.8.3: сначала базовые, затем дополнительные; внутри каждой группы по `sort_order`.

Цитаты ТЗ: §3.8.1 п.1 (492): «При назначении статуса и вида занятости в записях своего филиала предлагаются базовый набор (всегда) и справочник домашнего филиала (без скрытых записей).» §3.8.3 (494): «Порядок: базовые записи, затем дополнительные, внутри групп по порядку сортировки.»
