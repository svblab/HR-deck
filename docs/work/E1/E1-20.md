## Цель
`AvailabilityStatusService` и data-layer после E1-19: формат кода дополнительной записи по ADR-0010 §3; резерв базовых кодов §3; запрет создать дополнительную строку с резервным `code`. Создание дополнительного статуса принимает явный `owner_branch_id: int`; сервис проверяет, что филиал существует и не скрыт. Для записи справочника статусов, как на `origin/master`, остаётся `Permission.MANAGE_STATUSES` (`src/services/availability_statuses.py:57, 80, 99, 122`) — **модель прав карточка не меняет**. Lookup по паре owner+code — из E1-19.

## Не входит
Миграция схемы (E1-19); UI (E1-21); обмен пакетом (E8); формат кодов **видов занятости** (E1-13).
