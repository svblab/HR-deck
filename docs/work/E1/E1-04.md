## Цель
Классификатор и импорт: при том же `external_id` другое нормализованное ФИО или другой филиал дают CONFLICT и отклоняют пакет до записи; EXACT с теми же ФИО и филиалом проходит; локально обезличенная карточка и старый пакет с исходным ФИО — CONFLICT (15.7.5).

## Не входит
Запрет локального `update_employee` (E1-03); обезличивание (E10); ссылка вида по коду в пакете (E1-09); архивная реплика без подбора по ФИО (адденд ADR-0010 §8).

## Входные условия
1. `git show origin/master:src/services/employee_reconciliation.py | sed -n '54,60p'` -> CONFLICT только по ФИО, филиал не сравнивается.
2. Карточка E1-03 может быть не слита: импорт не должен обходить сервисный запрет через `apply_sync_row`.

## Критерии приёмки
1. `pytest tests/unit/test_employee_reconciliation.py tests/unit/test_employee_sync_import_conflict.py -q` -> проходит; тесты: расхождение `branch_id` -> CONFLICT; EXACT с теми же `full_name` и `branch_id` -> не CONFLICT; обезличенная локально + исходное ФИО в пакете -> CONFLICT, пакет целиком отклонён.
2. `rg -n "branch_id" src/services/employee_reconciliation.py` -> сравнение филиала в классификаторе присутствует.
3. `ruff check` и `mypy` по `allowed_paths` -> без ошибок.
4. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт.

## Что оставить после себя
Правки reconciliation/import, тесты, отчёт с «NOT VERIFIED» и «Для следующего».

## Заметки планировщика
Размер M по §7 аддендума. Репозиторий по-прежнему пишет переданные значения — политика в сервисе импорта (`src/services/employee_sync_import.py:571-578`; reconciliation `:56-60`). Обмен новыми кодами — E1-09.
