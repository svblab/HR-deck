## Цель
Классификатор и импорт: при том же `external_id` другое нормализованное ФИО или другой филиал дают CONFLICT и отклоняют пакет до записи; EXACT с теми же ФИО и филиалом проходит; локально обезличенная карточка и старый пакет с исходным ФИО — CONFLICT (15.7.5).

## Не входит
Запрет локального `update_employee` (E1-03); обезличивание (E10); ссылка вида по коду в пакете (E1-09); архивная реплика без подбора по ФИО для нового `external_id` (E1-09, docs/adr/ADR-0010-addendum-owner-code-identity-and-exchange.md §8).

## Входные условия
1. `git show origin/master:src/services/employee_reconciliation.py | sed -n '54,60p'` -> CONFLICT только по ФИО, филиал не сравнивается.
2. Карточка E1-03 может быть не слита: импорт не должен обходить сервисный запрет через `apply_sync_row`.

## Критерии приёмки
1. `pytest tests/unit/test_employee_sync_import_conflict.py tests/integration/test_adr0010_employee_reconciliation.py -q` -> код выхода 0; тесты: расхождение `branch_id` -> CONFLICT; EXACT с теми же `full_name` и `branch_id` -> не CONFLICT; обезличенная локально + исходное ФИО в пакете -> CONFLICT, пакет целиком отклонён.
2. `pytest tests/integration/test_adr0010_employee_reconciliation.py -q -k branch_id_mismatch` -> код выхода 0 (новый или переименованный тест сравнения филиала в классификаторе).
3. `ruff check src tests scripts` -> код выхода 0.
4. `mypy src` -> код выхода 0.
5. `pytest -q` -> код выхода 0.
6. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт.

## Что оставить после себя
Правки reconciliation/import, правки `tests/integration/test_adr0010_employee_reconciliation.py`, unit-тесты, отчёт с «NOT VERIFIED» и «Для следующего».

E1-09 criterion 3 меняет другое поведение в том же файле (`src/services/employee_reconciliation.py:61-71`, подбор по ФИО для архивных строк) — владелец правки подбора: E1-09; сравнение `branch_id` и CONFLICT по ФИО/филиалу — эта карточка (E1-04).
