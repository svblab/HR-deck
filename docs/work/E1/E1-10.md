## Цель
Отдельная функция нормализации и сравнения названий филиалов (strip, casefold, «ё»→«е», схлопывание пробельных Unicode-подряд); создание, переименование и импорт филиала отклоняют занятое название при другом `external_id`, включая скрытые филиалы; «А Б» и «АБ» — разные названия; `normalize_name_for_match` для ФИО не меняется.

## Не входит
Плановая численность (E1-11); организационные строки пакета кроме филиала; UI сообщений 7.19.7 (достаточно текста ошибки из сервиса).

## Входные условия
1. `git show origin/master:src/domain/employee.py | sed -n '100,102p'` -> `normalize_name_for_match` для ФИО.
2. `git show origin/master:src/services/directory_sync_import.py | sed -n '276,276p'` -> посимвольное сравнение названия в плане.

## Критерии приёмки
1. `pytest tests/unit/test_branch_name_normalization.py tests/unit/test_branch_name_uniqueness.py -q` -> проходит; пары «а  б» vs «а б» совпадают; «А Б» vs «АБ» — нет; занятое имя при другом `external_id` -> отказ создания/импорта/операции 7.19.7.
2. `rg -n "normalize_branch_name" src/` -> используется в `directories.py` и `directory_sync_import.py`.
3. `git show HEAD:src/domain/employee.py | sed -n '100,102p'` -> байт-в-байт как на `origin/master` (ФИО не тронуто).
4. `ruff check` и `mypy` по `allowed_paths` -> без ошибок.
5. `git diff --stat origin/master...HEAD` -> только `allowed_paths`, карточка, отчёт.

## Что оставить после себя
Модуль сравнения, правки сервисов, тесты, отчёт с «NOT VERIFIED» и «Для следующего».
