## Цель
Только схема и data-layer для `availability_statuses`: столбец `owner_branch_id INTEGER NULL REFERENCES branches(id)` (ADR-0010 §4); снятие столбцового `UNIQUE` на `code` (`0001_initial_schema.sql:74`) **без** `PRAGMA foreign_keys=OFF`; два частичных уникальных индекса. Lookup дополнительной строки по паре `(owner_branch_id, code)` в `AvailabilityStatusRepository` (`src/data/availability_statuses.py`).

**Перестройка** (как E1-08 / spike B1):
1. `PRAGMA defer_foreign_keys=ON`
2. `CREATE TEMP TABLE _availability_statuses_backup AS SELECT * FROM availability_statuses`
3. `DROP TABLE availability_statuses`
4. `CREATE TABLE availability_statuses` без столбцового `UNIQUE` на `code`, с `owner_branch_id`, сохранением `end_date_policy`, `color_hex`, `sort_order`, `is_archived`, `created_at`, `updated_at`
5. `INSERT INTO availability_statuses (id, code, name, end_date_policy, color_hex, sort_order, is_archived, created_at, updated_at, owner_branch_id) SELECT id, code, name, end_date_policy, color_hex, sort_order, is_archived, created_at, updated_at, NULL FROM _availability_statuses_backup`
6. `CREATE UNIQUE INDEX idx_availability_statuses_system_code ON availability_statuses(code) WHERE owner_branch_id IS NULL`
7. `CREATE UNIQUE INDEX idx_availability_statuses_owner_code ON availability_statuses(owner_branch_id, code) WHERE owner_branch_id IS NOT NULL`
8. `DROP TABLE _availability_statuses_backup`

Без `PRAGMA defer_foreign_keys=OFF` и без `PRAGMA foreign_key_check` в SQL миграции. Spike-факты — те же, что E1-08 (B1/B2/A1, 0010, OFF, runner, **не** использовать defer OFF перед COMMIT — STEP 0).
