## Цель
Только схема и data-layer для `availability_statuses`: столбец `owner_branch_id INTEGER NULL REFERENCES branches(id)` (ADR-0010 §4); снятие столбцового `UNIQUE` на `code` (`0001_initial_schema.sql:74`) **без** `PRAGMA foreign_keys=OFF`; два частичных уникальных индекса (базовые `owner_branch_id IS NULL` по `code`; дополнительные по `(owner_branch_id, code)`). Столбцы `sort_order`, `end_date_policy`, `color_hex` **не добавляются** — уже в `0001` (ADR-0010 §2.2). Lookup дополнительной строки по паре `(owner_branch_id, code)` в `AvailabilityStatusRepository` (`src/data/availability_statuses.py`); базовая — `code` и `owner_branch_id IS NULL`.

Перестройка `availability_statuses` — та же последовательность, что E1-08 (spike 2026-11-04): `PRAGMA defer_foreign_keys=ON`; `CREATE TEMP TABLE _availability_statuses_backup AS SELECT * FROM availability_statuses`; `DROP TABLE availability_statuses`; `CREATE TABLE availability_statuses` без столбцового `UNIQUE` на `code`, с `owner_branch_id`, сохранением `end_date_policy`, `color_hex`, `sort_order`; `INSERT … SELECT` с сохранением `id`; два частичных уникальных индекса; `DROP TABLE _availability_statuses_backup`; `PRAGMA defer_foreign_keys=OFF`; `PRAGMA foreign_key_check` пустой. Spike-факты: NOT NULL `status_history.status_id` (`0001:105`); RENAME-порядок без defer падает FK; OFF внутри txn не действует; OFF вне txn — запрет ТЗ §2.4.5 п.5.

Сервисные guard и резерв кодов (E1-20); UI (E1-21); обмен пакетом (E6/E8); виды занятости (E1-08).
