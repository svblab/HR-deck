## 6. Ловушки

- Пустые строки в чате теряются: тексты файлов передаются с `<<BL>>` и проверкой SHA-256 (`CONTEXT.md`).
- Веб-модели путают номера строк: читать файлы по ссылкам с хэшем коммита и требовать дословные цитаты.
- Cloud Agent не создаёт PR (его `gh` не авторизован, HTTP 401) и не сливает: PR открывает локальный Cursor через `gh` по команде Maintainer, сливает Maintainer; push только по явной команде и явным refspec.
- `work_status.py` сканирует `docs/work/*/*.md` кроме `_templates` и `reports`: файлы без front matter туда не класть.
- Слитые ветки удаляются только по команде Maintainer.
- Каждый промт Cloud Agent начинается с проверки среды (`uname -a` показывает Linux; сессия стартует в `/agent`, затем `cd /agent/repos/HR-deck`, `git rev-parse --show-toplevel` печатает `/agent/repos/HR-deck`), иначе стоп: правка F-01 в PR #174 по ошибке выполнена локальным Cursor на Windows (DECISIONS, 2026-11-02).
- Условие остановки в промте («если ворота не прошли, не пушить») исполнитель соблюдает буквально; нарушение — находка по §0 (PR #174, коммит 80e92cc).
- После смены модели Cloud Agent возобновляет прежнюю задачу служебным сообщением «Continue»; при остановке по ошибке в FIND это привело к коммиту без команды Maintainer (docs-PR закрытия E0, 2026-11-02). После смены модели начинайте новую задачу; остановку снимает только новая команда Maintainer.
- Исполнитель вставляет сырой полный вывод команд гейтов, не пересказ. В E0 это нарушалось дважды; повтор — находка по §0.
- Хуки Cloud Agent добавляют в каждый коммит трейлер `Co-authored-by` чужой учётной записи, в том числе после `--amend`: допустим только он (`DECISIONS.md`, 2026-11-07), конфигурацию не менять, хуки не обходить, `--no-verify` не использовать; при squash-слиянии в `master` трейлера нет.
- Самооценка исполнителя («PASS» без вывода) ненадёжна: принимать только полные 40-символьные SHA и вывод команд в тексте отчёта, проверять по `git`.
- Блок защиты проекта в каждом промте (решение Maintainer, 2026-11-10): первыми строками `PROJECT GUARD`, `TASK-ID` (повторяется первой строкой ответа), проверка `git remote get-url origin` и точного пути рабочей папки, иначе ответ `WRONG PROJECT`; веб-рецензенту вместо команд — цитата `id:` и `branch:` из карточки. Ответ без TASK-ID не принимается.
- `git diff --check` запускать после последней правки отчёта и командой `git diff --check origin/master HEAD`, а не `origin/master` по рабочему дереву: так остались пробелы в отчёте E1-04.
- Тесты нового кода не закреплять на номерах миграций и размерах справочников (`applied[-1]`, не жёсткие числа); перед миграционной карточкой делать grep по тестам на `current_version(...) == N`, `applied == [N]` и число пунктов справочника.
