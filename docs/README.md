# Документация проекта — «Журнал доступности персонала»

Порядок чтения для нового участника (включая Cursor в начале новой сессии):

1. **`ТЗ_HR_uchet_dostupnosti.docx`** (вне этой папки, поставляется отдельно) —
   источник требований. Всё остальное — производное от него.
2. **`ANCHOR_CORE.md`** — незыблемые архитектурные решения и инварианты.
   Прочитать перед первой задачей.
3. **`ANCHOR_PROTOCOL.md`** — как мы работаем: ветки, коммиты, ADR, ревью,
   definition of done. Обязателен перед первым PR.
4. **`ROADMAP.md`** — эпики, их границы, зависимости и трассировка на разделы
   ТЗ.
5. **`TESTING.md`** — что и как тестируется, что блокирует мерж.
6. **`report-templates-guide.md`** — подготовка пользовательских Excel/PDF-шаблонов
   (EPIC-011); образцы в `templates_samples/`.
7. **`manual/`** — комплект пользовательской и эксплуатационной документации
   (EPIC-017): руководства, установка, runbook, шпаргалка.
8. **`promo/`** — рекламный буклет продукта (EPIC-017).
9. **`adr/`** — принятые архитектурные решения. `ADR-TEMPLATE.md` — шаблон
   для новых.

## Статус документов

Все документы в этой папке — живые, редактируются по мере развития проекта.
Любое изменение `ANCHOR_CORE.md`, меняющее уже принятое архитектурное
решение (таблица в разделе 1 файла), само по себе требует ADR — см. правило
п.4.6 в `ANCHOR_PROTOCOL.md`.
