# ADR-0004: Политики аутентификации (задержка входа, резервный код, KDF)

Статус: Принято
Дата: 2026-08-26
Автор: Cursor (EPIC-003)
Затронутый EPIC: EPIC-003

## Контекст

ТЗ §4.2 требует: хэш пароля с солью; автоблокировку по бездействию
(по умолчанию 15 минут, настраивается); задержку после неудачных попыток
входа (настраивается). Точная прогрессия lockout и форма хранения
резервного кода в ТЗ не детализированы. По `ANCHOR_PROTOCOL` нельзя
молча изобретать политику, влияющую на безопасность входа.

## Рассмотренные варианты

### Задержка после неудачи

1. Фиксированная настраиваемая задержка после каждой неудачи (вкл/выкл).
2. Экспоненциальный backoff / временная блокировка учётки.

### Резервный код

1. Хранить только верификатор (KDF-хэш + соль) в зашифрованной БД; plaintext
   только в UI один раз.
2. Хранить код обратимо (для повторного показа) — отвергнуто ТЗ/EPIC.

### KDF паролей

1. Argon2id с параметрами в одном модуле.
2. PBKDF2-HMAC-SHA256 — запасной вариант, если Argon2 недоступен.

## Решение

1. **Задержка:** вариант 1. По умолчанию 2 секунды после неуспешной попытки;
   Администратор может изменить длительность или отключить. Одна и та же
   задержка применяется и при «неизвестный логин», и при «неверный пароль»,
   чтобы не усиливать enumeration. Сложная прогрессия не вводится без
   отдельного изменения ТЗ.
2. **Резервный код:** только верификатор Argon2id в таблице `recovery_codes`;
   после успешного восстановления код помечается использованным и не
   принимается повторно; выпускается новый код (показ один раз).
3. **KDF:** Argon2id (`argon2-cffi`); параметры и кодирование хэша — только в
   `domain.password_kdf`. Тот же KDF (raw) используется для вывода ключа
   обёртки мастер-ключа (ADR-0003).

## Последствия

- UI не реализует задержку самостоятельно — только сервис аутентификации.
- Смена параметров KDF потребует миграции/перехэширования (отдельная задача).
- Настройки таймаута/задержки хранятся в `app_settings` и меняются только
  с правом `manage_security_settings`.

## Как проверяется

Unit: матрица прав, таймаут сессии без real sleep, KDF/verify.
Integration: setup/login/lock/recovery/account management + audit atomicity;
отсутствие паролей/кода в `technical_events` / `user_action_log`.
