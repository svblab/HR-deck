# ADR-0012 Addendum — Массовое применение автосопоставленных строк конвертации

Статус: Принято (2026-09-28)
Дата: 2026-09-28
Автор: Claude (архитектурный обзор)
Затронутый EPIC: EPIC-018 (вкладка «Конвертация данных», уже закрыт/смержен) — это дополнение к принятой ADR-0012, не переоткрытие её целиком
Зависит от: ничего нового технически; переиспользует существующий `EmployeeConversionService.save_row` без изменений его контракта

## Контекст

Текущий `run_conversion_wizard_flow` (`src/ui/conversion_wizard_dialog.py`) после `ingest_file` сразу открывает `ConversionWizardDialog` на первой оставшейся строке (`rows[0]`) и ведёт построчно: сопоставление филиала/отдела/подразделения/должности через `_select_combo_by_text` (точное совпадение текста без учёта регистра; при отсутствии совпадения комбобокс остаётся на плейсхолдере), предупреждение о возможном дубле по ФИО (`_update_duplicate_warning` — **не блокирует** сохранение, только предупреждает), «Сохранить»/«Пропустить» по одной строке за раз.

Найдено при подготовке: **группового применения сейчас нет вообще** — ни чекбоксов, ни списочного экрана, только один ряд за раз. `EmployeeConversionService.save_row` уже атомарен и коммитится независимо на каждый вызов — специальной инфраструктуры для батча создавать не нужно, только цикл по уже существующему методу.

## Решение

Перед открытием построчного `ConversionWizardDialog` показывается **отдельное модальное окно** (аналогично `TransportImportPlanDetailsDialog` из ADR-0013 — свой `QDialog`, не встроенная страница внутри вкладки) со списком **всех** оставшихся строк сессии с чекбоксом у каждой. Строка автоматически классифицируется как:

- **Готово к применению** (чекбокс включён и по умолчанию отмечен) — если одновременно:
  - филиал, должность и тип занятости однозначно сопоставились по точному тексту (без учёта регистра) с существующей, неархивной записью справочника. **Решено 2026-09-28: логика сопоставления дублируется отдельно для нового модального окна, а не выносится в общую функцию** — `conversion_wizard_dialog.py` и его тесты не трогаются вообще, риск регрессии в уже смерженном и протестированном коде исключён ценой одной небольшой дублирующей функции сравнения текста;
  - отдел/подразделение либо не указаны в исходной строке, либо тоже однозначно сопоставились;
  - по ФИО **нет** совпадения через `EmployeeService.search_by_name` + `normalize_name_for_match` — то же правило, что сейчас показывает баннер дубля, только здесь оно не предупреждает, а **исключает строку из массового применения**, чтобы batch-режим не мог тихо обойти защиту, которая в построчном режиме была лишь предупреждением, но человек её видел перед кликом «Сохранить».
- **Требует проверки** (чекбокс недоступен) — всё остальное: несопоставленное или архивное значение справочника, отсутствие обязательного поля, найденный дубль по ФИО. Такие строки не показываются с деталями на этом экране — как и раньше, попадают в существующий построчный `ConversionWizardDialog` без изменений его кода и поведения.

Кнопка «Применить отмеченные (N)» вызывает новый `EmployeeConversionService.save_rows_bulk(session_id, resolved_rows, last_accessed_at)`: цикл по `save_row` для каждой выбранной строки, **без новой транзакционной семантики** — как и сейчас, каждая строка коммитится независимо; при ошибке на одной строке батч не прерывается, ошибка собирается в отчёт, остальные строки продолжают обрабатываться. После применения — сводка (создано: N, ошибок: M с текстом) и переход к построчному визарду для оставшихся «требующих проверки» строк (как раньше).

Массового пропуска («Пропустить отмеченные») **не делается** — Johan просил только применение, не пропуск; если понадобится, это отдельное небольшое расширение позже.

## Явно вне рамок

- Изменение самого построчного `ConversionWizardDialog` и его существующих тестов — код только читается (для извлечения общей функции сопоставления), поведение не меняется.
- Настраиваемые правила «готовности» (например, разрешить дубль по ФИО с явным подтверждением) — сейчас дубль всегда исключает из batch, без промежуточных вариантов.

## Решения по открытым вопросам (2026-09-28)

1. Общая функция сопоставления **не** выносится — новая логика для модального окна дублируется отдельно, `conversion_wizard_dialog.py` не трогается совсем (ни код, ни тесты).
2. Список строк — **отдельное модальное окно**, свой `QDialog`, тот же паттерн, что `TransportImportPlanDetailsDialog` в ADR-0013.
